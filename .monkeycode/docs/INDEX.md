# RaftLab 文档

## 项目概述

RaftLab 是一套带确定性仿真与故障注入的 Raft 实现及判定器，把「共识能跑」变成可测量、可重放、可证伪的断言。

**目标用户**: 协议实现者、测试基础设施作者、需要把共识正确性钉死的工程师。

**核心价值**:
- 同种子同场景事件日志字节级可重放
- 运行时 9 条不变量常开，客户端线性一致性双检查器交叉验证
- 8 个故意写错的 Raft 变体必须被抓住，漏一个即检查器太弱

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 语言 | Go 1.22+ | goroutine/channel 映射节点与收件箱，单一静态二进制，-race/pprof/testing 齐全 |
| 仿真 | 虚拟时钟 + 单线程事件调度器 | 运行顺序是种子的纯函数，无数据竞争 |
| 持久化 | 自研 WAL（CRC32-C + 可配置 fsync） | 撕裂写可检测，测试用内存存储对照 |
| 线性一致 | 自研 Wing–Gong + porcupine 交叉验证 | 两个独立判定器结论不一致即失败 |
| 许可证 | MIT | 仓库侧明确要求 |

## 核心功能

### 确定性仿真
- **目的**: 同种子同场景 → 事件日志字节级一致
- **描述**: 虚拟时钟、单线程调度、每参与者独立派生随机流

### 故障注入
- **目的**: 14 种可组合故障，脚本化时间切换
- **描述**: 延迟/丢包/重复/乱序/位翻转/分区/崩溃/撕裂写/慢盘/时钟偏移/陈旧重加入

### 判定器
- **目的**: 把正确性变成测试信号
- **描述**: 9 条运行时不变量 + 客户端线性一致性 + 活性只报告不断言

### 变异测试
- **目的**: 证明检查器足够强
- **描述**: `internal/unsafe` 中 8 个经典 bug 变体，每一个都必须被抓住
